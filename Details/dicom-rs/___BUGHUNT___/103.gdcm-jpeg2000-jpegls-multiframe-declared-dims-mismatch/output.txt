=== Confirming the multi-frame code path is genuinely different from candidate 100's ===

Temporary #[test] `bughunt_check_fragment_count` (reverted), printing `SequenceOfFragments::fragments().len()` for both fixtures before any patching:

pydicom/emri_small_jpeg_2k_lossless.dcm: fragments=10
pydicom/emri_small_jpeg_ls_lossless.dcm: fragments=10

Since `pixeldata/src/gdcm.rs` only calls `decode_multi_frame_compressed` (dims[2] = number_of_frames,
here 10) when `fragments.len() > 1`, this confirms both crashes above went through GDCM's
per-fragment loop in `JPEG2000Codec::Decode`/`JPEGLSCodec::Decode`'s `NumberOfDimensions == 3`
branch with `Dimensions[2] == 10`, genuinely processing 10 fragments/frames in one decode call -
not the `Dimensions[2] == 1` single-fragment case candidate 100 used.
