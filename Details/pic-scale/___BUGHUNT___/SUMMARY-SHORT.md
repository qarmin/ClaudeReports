| 004 | logic | Yes | AVX-512 alpha-check drops row remainder | `row.as_chunks::<64>().0` in `avx512_has_non_constant_cap_alpha_rgba8` skips 0-63 trailing bytes per row, so non-constant alpha there goes undetected and premultiply/unpremultiply is silently skipped on AVX-512BW hosts |
| 006 | logic | Yes | AVX2/SSE u16 premultiply wrong for bit_depth==16 | "any bit depth" path uses an f32-reciprocal approximation instead of the crate's exact div_by_65535, diverging +/-1 LSB from the scalar reference on ~38% of a downscale test's seeds |
| 007 | logic | Yes | AVX2 u16 unpremultiply zeroes color on zero-alpha pixels | `avx_unpremultiply_alpha_rgba_u16_row_avx` blends in an all-zero vector for alpha==0 pixels instead of the original pixel (SSE already does this correctly), discarding nonzero premultiplied color left by negative-lobe (Lanczos-family) resize ringing |
| 008 | logic | Yes | AVX2/SSE u16 unpremultiply cvtps_epi32 overflow at alpha==1 collapses color to 0 | unclamped `color * (max_colors/alpha)` overflows i32::MAX at bit_depth==16/alpha==1/color>=32769, producing the x86 "integer indefinite" value which packus_epi32 saturates to 0 instead of max_colors; reproduced via a real Ginseng-filter 10000->9999 downscale |
| 009 | logic | No - needs adversarial convolution ringing not achieved via public API this session | AVX2 u8 unpremultiply packus_epi32/mulhi_epu16-then-packus_epi16 signedness cascade | `_mm256_packus_epi32`/`_mm256_mulhi_epu16` can produce a value >=32768 that the following `_mm256_packus_epi16` reinterprets as negative, collapsing color to 0 instead of clamping to 255, whenever stored alpha is near 1 and stored premultiplied color is large; SSE already used the correct signed-saturating pack and is unaffected |
| 010 | crash | Yes | Unvalidated `source_size` overflows an unchecked multiply in filter-weight generation | `plan_generic_resize` only overflow-checks `destination_size`; an unvalidated huge `source_size` drives `kernel_size * out_size` (`src/math/weights.rs`) past `usize::MAX` via a plain `*`, panicking instead of returning `Err` in a debug/overflow-checked build |
| 011 | logic | Yes | AVX2/SSE u8 unpremultiply `rcp_ps` approximation diverges +/-1 from the scalar reference | `_mm256_rcp_ps`/`_mm_rcp_ps`'s ~12-bit hardware-approximate reciprocal (not `cvtps_epi32`'s rounding mode, as originally suspected) diverges by +/-1 from the exact round-half-up scalar formula on ~2-36.5% of a real downscale's output bytes; fixed for AVX2-PreferQuality/SSE via exact division + explicit round-half-up; AVX2-PreferSpeed (default)'s own fixed-point-mulhi scheme has a separate, unrelated, unfixed error source |
