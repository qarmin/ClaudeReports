Interpretation: on the pristine fragmented MP4 (`frag.mp4`), every seek across the file's duration
resolves correctly via the real `IsoMp4Reader::seek` -> `MoofSegment::ts_sample` ->
`TrunAtom::ts_sample` path. On the same file with every `tfhd.default_sample_duration` zeroed
(`evil.mp4` - the exact crafted-fMP4 scenario the candidate describes), every seek fails with a
real, explicit `SeekError(OutOfRange)` - not a silent, wrong-but-successful sample resolution.

surfacing an error"): an error *is* surfaced, consistently, for every timestamp tried, including
t=0.0s (the very first sample).
