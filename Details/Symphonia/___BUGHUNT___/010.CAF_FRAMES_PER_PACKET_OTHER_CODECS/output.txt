Note: `max_frames_per_packet`/`frames_per_block` show the fully attacker-controlled value
(0xFFFFFFF0 = 4294967280) reaching AudioCodecParameters unmodified for AAC/MP3 (the Fixed-packet
path) - confirming the CAF demuxer really does pass it through untouched for these codecs too, the
same as it does for ima4. The fact that nothing downstream panics is because none of these
decoders' own decode paths read that field back for buffer indexing (AAC/MP3: never read it at
all; ALAC/FLAC: overwrite it with a value parsed from their own codec-specific extra data before
constructing any buffer) - see RESULT.md for the full breakdown per codec.
