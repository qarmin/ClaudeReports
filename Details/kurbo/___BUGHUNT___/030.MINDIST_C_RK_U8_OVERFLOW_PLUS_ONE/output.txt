=== Approach 2: manual boundary-value construction, exhaustive over all n in 0..=255 ===
(pure math check, run standalone, not part of the Rust build - see RESULT.md for the derivation)

$ python3 - <<'EOF'
maxu = 0
worst = None
for n in range(256):
    two_n = (2*n) % 256  # matches u8 wrapping-mul semantics used in release builds
    max_r_Drk = two_n - 1 if two_n > 0 else -1   # exclusive range used in min_dist_param's own loops
    max_r_S = two_n                               # inclusive range used in S()
    for max_r in (max_r_Drk, max_r_S):
        if max_r < 0:
            continue
        upsilon = min(max_r, n)
        if upsilon > maxu:
            maxu = upsilon
            worst = (n, max_r, upsilon)
print("max upsilon ever reachable:", maxu, "at (n, max_r, upsilon) =", worst)
EOF
max upsilon ever reachable: 254 at (n, max_r, upsilon) = (255, 254, 254)

  -> Every real call site passes `r`/`k` values generated from a range bounded by `2 * n`/`2 * m`
     computed in that *same* `n`/`m`'s `u8` arithmetic, so `r.min(n)` (`upsilon`) can never reach
     255 - the wraparound of `2 * n` structurally caps it at 254, and `254 + 1 = 255` fits `u8`
     cleanly. So `upsilon + 1` (or `varsigma + 1`) can never actually overflow through any call path
     that starts at `min_dist_param`/`S`/`D_rk`.
