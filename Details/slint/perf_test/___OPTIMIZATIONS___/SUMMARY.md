# Optimization candidates - index

`BATCH_SWEEP.md` is a sweep across every axis the harness has - mostly confirmations and nulls, plus
the two findings that came out of it. `NEXT_CANDIDATES.md` is the plan for what to look at next - unmeasured, with a null condition
written for each.

Read `PIPELINE.md` for the harness. `TEN_IDEAS.md` sizes ten optimization ideas by ablation
(six were worth nothing); `PER_FIX_ISOLATED.md` measures each applied fix on its own. `TODAY_END_TO_END.md` has the combined before/after for
everything applied in the latest session. One row per candidate, details in its folder.
Status: **win** = measured improvement, **null** = no improvement or not a real problem,
**open** = quantified, fix not implemented here.

Real-hardware confirmation of the applied set: `rects` -14.2%, `scroll` -10.8%, gradient -5.9%,
`list` -2.5% (`GPU_RESULTS.md`). Candidate 03 landed after that run and is software-renderer only so
far; it needs a `just gpu-quick` to be reconfirmed on the GPU.
