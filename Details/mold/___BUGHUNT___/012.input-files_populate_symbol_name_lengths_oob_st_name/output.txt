4. BEFORE fix - build-asan (-DMOLD_USE_ASAN=ON, g++), unpatched, commit c340272e
=====================================================================

$ ./build-asan/mold -o /tmp/out.exe /tmp/evil.o

Repeated 4 times total, all 4/4 identical exit 139, SIGSEGV. No `AddressSanitizer:` diagnostic was
printed on any of the 4 runs - this matches this project's own known quirk (candidate 009's
lesson, ___BUGHUNT___/README.md): the crash happens inside a oneTBB worker thread
(read_input_files()'s parallel_for_each), and ASAN does not always print a report for a genuine
SIGSEGV delivered in a worker thread. The exit code (139 = 128+SIGSEGV) and the plain-build gdb
backtrace above are the confirmation for this case, not an ASAN report.
