Mechanism: x = 1.0e30_f32 makes x*x overflow f32 range to +inf (f32 max ~3.4e38, so
(1e30)^2 = 1e60 rounds to +inf). y = x*x/4.0 = +inf. t = y = +inf. Loop condition
`t > 1e-12` is true for +inf (unlike NaN, +inf compares normally). s += t makes s = +inf.
t *= y / (i*i) = +inf * (+inf/4) = +inf - t never decreases once it becomes +inf, so the
loop condition stays true forever: genuine unbounded loop, confirmed by direct measurement,
not merely reasoned about.

=== Why this is not reachable through generate_weights (the only real caller) ===
src/compute_weights.rs's generate_weights is the sole place in the crate that ever calls a
`ResamplingFilter.kernel` function pointer (kaiser is installed via
`ResamplingFilter::new(kaiser, 2f32)` in src/sampler.rs:281, which sets `window: None`,
`is_resizable_kernel: true`). In the `window_func` == None branch (compute_weights.rs:136-139):

    let dx = dx.abs();
    weight = resampling_function(dx * filter_scale);

- `dx.abs()` is non-negative for any real `dx` (and if `dx` were NaN, `.abs()` keeps it NaN, it
  does not become negative).
- `filter_scale = 1.0 / filter_scale_cutoff`, and `filter_scale_cutoff = scale.max(1.0)` (or a
  constant `1.0` for non-resizable kernels), so `filter_scale` is always in `(0.0, 1.0]` -
  strictly positive - whenever `in_size`/`out_size` are themselves finite and positive.
- `dx` itself (`k.as_() - center`) is bounded by the already-computed `start..end` window, which
  in turn is bounded by `in_size`/`filter_radius`, both finite for any input that has already
  passed the crate's own size/overflow validation (see candidate 009's already-fixed length
  checks) - so `dx` cannot become NaN or unboundedly large through this path either.

grep across the whole crate confirms `kaiser` has exactly one call site (src/sampler.rs:281,
installing it as `resampling_filter.kernel`) and `bessel_i0` has exactly two call sites, both
inside `kaiser` itself (src/math/kaiser.rs:75-76), with the second call's argument bounded to
`[0, 6.33]` (valid `|x|<=1`) or `NaN` (out-of-domain `|x|>1`, sqrt of a negative) - never a large
finite value. So `x >= 0` and bounded on entry to `kaiser`, and `bessel_i0`'s argument is always
either small-and-finite or exactly `NaN` (which exits the loop immediately, per the finding
above) - never the "+inf, not NaN" shape that was shown above to actually hang.
