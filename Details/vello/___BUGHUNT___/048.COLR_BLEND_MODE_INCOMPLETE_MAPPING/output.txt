=== AFTER (patch.diff applied to vello/src/scene.rs) ===
Ran `cargo run --release` 3 times against a rebuilt path-dependency build with patch.diff applied -
identical output all 3 times:

$ cargo run --release
     Running `target/release/colr_blend_mode_incomplete_mapping_repro`
Encoded BEGIN_CLIP blend_mode words: [
    0x8003,
    0x0003,
    0x0103,
]
PaintComposite(mode=Multiply) was encoded as Compose::SrcOver + Mix=1 (expected Mix::Multiply=1; Mix::Normal=0 is what the bug produces)
did not reproduce - Mix::Multiply was correctly encoded
$ echo "exit code: $?"
exit code: 0

The only bit that changes between the two runs is the third BEGIN_CLIP's Mix nibble (0x0003 ->
0x0103): the outer `push_layer(CompositeMode::SrcOver)` wrapper that `skrifa`'s own paint-graph
traversal always emits around a `PaintComposite` node (see RESULT.md's root cause) stays at 0x0003
in both cases - it was never wrong, since `SrcOver` is one of the explicitly handled Porter-Duff
arms in the original `match`. Only the second, real `push_layer(*mode)` call - the one that carries
the font's actual `CompositeMode::Multiply` - changes from Mix::Normal (bug) to Mix::Multiply (fix).
