Note: the literal point values from issue #1277, run unmodified through the current `fill()`
public API (which since PRs #1341/#1519/#1559 also takes a `cull_bbox: RectU16` parameter that
did not exist when #1277 was filed), no longer reach the vulnerable code at all - every point in
that exact curve has a y-coordinate several orders of magnitude below any u16-representable
cull-bbox top, so the whole curve is discarded by flatten()'s "fully outside the cull bbox" cull
check before `flatten_cubic_simd` is ever called. This is incidental (the cull check was added for
performance, not as a fix for #1277) and doesn't hold for curves that are only partially/nowhere
near being fully outside the cull bbox - see `on_screen_extreme_control_points()` in repro/src/main.rs,
which reproduces the exact same crash through the exact same public entry point.
