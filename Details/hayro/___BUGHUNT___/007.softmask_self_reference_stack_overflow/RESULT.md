# softmask_self_reference_stack_overflow

`hayro-interpret/src/x_object/soft_mask.rs` `SoftMask` looked suspicious as the same missing-
depth-check shape as the now-fixed `TilingPattern` (candidate 002) and `Type3` (candidate 005): a
grep of `begin_nested_interpretation`/`end_nested_interpretation` call sites showed only
`x_object/form.rs` calls either, and `SoftMask::interpret` doesn't call them directly - suggesting
a soft mask whose own group content stream sets a soft mask again (a self-referential ExtGState)
might recurse unboundedly through `SoftMask::interpret`.

## What was tried

| Approach/tool | Config (build/input/duration) | Outcome |
|---|---|---|
| Hand-built minimal PDF (`self_softmask.pdf`, generated by `make_pdf.py`) with an ExtGState `/R1` whose `/SMask /G` points at a transparency-group Form XObject that itself applies `/R1 gs` again before filling - a directly self-referential soft mask | Standalone `repro/` crate depending on the real `hayro` public API (`hayro::render`), run in a child process (release build) so a stack overflow, if any, is observed as an abnormal exit rather than corrupting the test harness. 3 repeat runs. | Did not reproduce - `render()` returns a valid 200x200 pixmap every time, ~4-5ms, exit code 0. |
| Same PDF with a temporary `eprintln!` added at the top of `SoftMask::interpret` to trace the actual nesting depth reached, reverted before write-up | Debug trace only, same repro binary, release build | `nesting_depth` climbs 1, 3, 5, ... 51, then recursion stops and rendering completes successfully - see `output.txt`. |

## Status

**Not reproducible.** Covered: a directly self-referential soft mask (`ExtGState` -> `SMask.G` ->
Form XObject whose own content stream re-applies the same `ExtGState`) via 1 crafted PDF, 3 repeat
runs, plus a depth-tracing run confirming *why* it terminates rather than just that it does. A
longer fuzzing campaign against `fuzz_pdf_render` might turn up an indirect cycle (soft mask A's
group references a pattern/Type3 glyph that in turn references soft mask A again) that this direct
single-object cycle didn't exercise, but that's a different, unchecked shape - see "What's not
done" below.

## Root cause

Not a bug: the depth limit *is* enforced for this path, just not inside `SoftMask::interpret`
itself, which is why the original grep-based suspicion (candidate 002's root-causing note) missed
it.

`SoftMask::create`/construction computes `nesting_depth = context.nesting_depth() + 1`
(`soft_mask.rs:113`) and stores it on the `SoftMask`. `SoftMask::interpret` then builds a *new*
`Context` via `Context::new_with(..., self.0.nesting_depth)` (`soft_mask.rs:135-143`), i.e. it
seeds the fresh context's internal `nesting_depth` counter with that already-incremented value
before calling `self.0.group.draw(...)`. The mask's `group` is itself a transparency-group Form
XObject, and `FormXObject::draw` (`x_object/form.rs:56`) calls `context.begin_nested_interpretation()`
before recursing into its content stream - which checks `nesting_depth >= MAX_NESTED_INTERPRETATION_DEPTH`
(50, `context.rs:333`, `context.rs:21`) and returns `false` (aborting that branch, logging
`"interpreter nesting depth exceeded"`) once the cap is hit.

So a self-referential soft mask does recurse, but each round-trip (`SoftMask::interpret` ->
`FormXObject::draw` -> content stream re-applies the `ExtGState` -> new `SoftMask::interpret` for
the next occurrence) passes the same threaded depth counter through both layers, and
`FormXObject::draw`'s existing check (added for the general Form XObject recursion case, not
specifically for soft masks) catches it at the same 50-deep cap used everywhere else - it just does
so indirectly, via the depth value `SoftMask` forwards into the group's own context, not via a
check local to `soft_mask.rs`. No stack overflow: recursion is bounded by the same mechanism that
already protects `FormXObject`/`TilingPattern`/`Type3`, it's just not obviously visible from
`soft_mask.rs` alone.

## The fix

No fix - there is nothing to fix, the existing depth propagation already covers this path
correctly.

- Project test suite: not run (no code changed).

## What's not done / open questions

- Only a *direct* self-reference (soft mask -> its own group -> same `ExtGState` again) was tried.
  An *indirect* cycle through a different recursive construct (soft mask A's group content uses a
  tiling pattern or Type3 glyph whose own content sets soft mask A again) crosses between
  `soft_mask.rs`, `pattern.rs`, and `font/type3.rs`'s three independent `nesting_depth` fields -
  each is seeded from `ctx.nesting_depth() + 1` at construction time the same way, so the same
  threading argument above should still apply, but this specific cross-construct cycle shape was
  not built and run this session.
- Not fuzzed - only one hand-built PDF was tried. `fuzz_pdf_render` (restored this session, see
  `../README.md`) covers this whole code path already; a longer run against it (via `fuzz-bug-repro`,
  run separately) is more likely to surface an indirect cycle than more hand-built PDFs would.
