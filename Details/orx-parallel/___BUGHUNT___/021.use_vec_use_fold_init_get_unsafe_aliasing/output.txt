This compile-time rejection *is* the fix working (same reasoning as candidate 002's justfile note):
`init_get` was a safe fn that could be called an unbounded number of times for the same
`thread_idx` from `&self`, producing aliased `&mut` references from 100% safe caller code. After
the patch it is `unsafe fn`, so this exact repro (which deliberately calls it twice with no
`unsafe` block, to demonstrate the pre-patch soundness hole) now fails to compile instead of
compiling and exhibiting UB - the repro is not "broken", the caller-side misuse it was built to
demonstrate is no longer expressible without an explicit `unsafe` block.
