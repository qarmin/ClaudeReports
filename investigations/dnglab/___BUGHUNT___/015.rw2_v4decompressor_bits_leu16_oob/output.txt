=== Fix verified against a second, different-length truncation of the same real file ===

Truncating the same real crash-report file to 90% of its original length (a different byte length
than the original 525764-byte file, same bug class - same `decode_panasonic_v4`/BitPumpPanasonic
code path, still runs out of source bytes mid-row) also panics before the patch (same
bits.rs:207/v4decompressor.rs:12 pair, RAYON_NUM_THREADS=1, 1/1 tried) and decodes cleanly
(no panic) after the patch is applied - confirms the fix isn't narrowly tied to the exact original
473187/525764-byte boundary. More aggressive truncations (70%/50%/30%) hit an unrelated, already
correctly-handled I/O bounds check further up the RW2 decode pipeline
(`subview_until_eof_padded(): Offset ... is behind EOF`, returned as a graceful `Result::Err`, not
a panic) before ever reaching `decode_panasonic_v4` at all - out of scope for this candidate.
