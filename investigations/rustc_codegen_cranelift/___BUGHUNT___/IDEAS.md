Workspace hazard recorded by candidates #020 and #024 - not a suspect, so it deliberately has no
backlog row: `git stash` uses a single shared `refs/stash` for *all* worktrees of one repo, so two
candidates stashing in parallel worktrees swapped each other's patches this session (detected and
repaired). Use `git diff > file` + `git checkout --` in a worktree instead of `git stash`.
Relatedly, a `./y.sh build` in the same wall-clock second as the source change can leave cargo
thinking the backend is already fresh, so a post-patch test run can silently exercise the
*unpatched* `.so` - check its mtime before trusting a before/after comparison.

Baseline numbers that session measured, for context when re-running anything: 19154 hodow tests,
13833 pass (72.2%), 5318 trap as unimplemented (27.8%), 3 produce a wrong value. Per intrinsic:
5185 distinct, 3116 fully OK (60.1%), 2066 entirely unimplemented (39.8%), 3 wrong. LLVM baseline
on the same source: 19154/19154 pass.
