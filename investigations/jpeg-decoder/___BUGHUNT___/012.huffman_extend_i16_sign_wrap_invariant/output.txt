This crafts two real, on-the-wire JPEG files, each with a custom DHT table whose single 1-bit
Huffman code maps directly to the raw symbol byte 0xFF (255, the maximum byte a DHT segment can
ever encode as a Huffman leaf value) - once as the DC symbol (decoder.rs:1105's `1..=11` call site),
once as the AC symbol (decoder.rs:1165's call site, reached via `s = byte & 0x0f`). Both are fed to
the real public `jpeg_decoder::Decoder::decode()` entry point. The DC case is rejected by the
`_ => Err(...)` arm before ever reaching `receive_extend`/`extend`. The AC case succeeds because
`s = byte & 0x0f` masks any byte value down to 0..=15 before it is ever used as the `count` argument.
Neither run triggered the temporary debug_assert.

This targets decoder/lossless.rs:93 specifically, the exact call site named in the candidate
description, via three crafted real SOF3 (lossless) JPEGs each with a custom DHT table whose 1-bit
code maps to a chosen raw symbol byte:
  - symbol 16: the code's own explicit bypass case - `16 => 32768` assigns the difference directly
    as an i32 without ever calling extend()/receive_extend(). Confirmed Ok, no panic.
  - symbol 0xFF (255): outside the 0..=16 range entirely, hits the `_ => Err(...)` arm before
    reaching extend(). Confirmed Err, no panic.
  - symbol 15: the legal boundary value, which does call `receive_extend(reader, 15)` ->
    `extend(value, count=15)`. Confirmed Ok, no panic - this is the maximum count value any
    reachable call site can ever pass to extend().
