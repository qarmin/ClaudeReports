=== Approach 2: git bisect-by-inspection of what changed between 0.3.1 (panics) and 0.3.2 (doesn't) ===

$ git log --oneline c1a1fe0..95550d7 -- src/
95550d7 Fix panic when prediction calculation is invalid (#282)

Exactly one src/ commit landed between the two releases, and it is the fix for issue #282:

diff --git a/src/parser.rs b/src/parser.rs
@@ parse_sos()
+    if point_transform >= frame.precision {
+        return Err(Error::Format(
+            "invalid point transform, must be less than the frame precision".to_owned(),
+        ));
+    }

Combined with the pre-existing (older) guard in src/decoder.rs's SOF handling:
    if !(2..=16).contains(&frame.precision) {
        return Err(Error::Unsupported(UnsupportedFeature::SamplePrecision(frame.precision)));
    }
this guarantees, by the time decode_scan_lossless's line 112 runs:
  frame.precision (u8) is in [2, 16]      (checked at SOF time, decoder.rs)
  scan.point_transform (u8) < frame.precision   (checked at SOS time, parser.rs)
=> frame.precision - scan.point_transform >= 1
=> frame.precision - scan.point_transform - 1 >= 0   (no underflow possible, u8 arithmetic)
