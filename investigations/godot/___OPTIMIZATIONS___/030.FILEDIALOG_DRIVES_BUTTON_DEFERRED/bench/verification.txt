=== BASELINE CONTROL ===

SCRATCH_DRV after set_access + set_current_dir: MenuButtons=2 current_dir='/home/rafal/.cache'

Reading: a fresh FileDialog has 2 MenuButtons on baseline (the file-sort button and the drives
button) and 1 with the patch (sort only). Once the dialog is actually used - set_access() +
set_current_dir(), which is what runs _update_drives() - the patched build creates the drives
button too and both builds end at 2, with the same resulting current_dir. So the drives button is
deferred, and the directory-change path whose guard reads drives->is_visible() still works.

NOTE the drive_count=19: this Linux system reports 19 "drives", because Godot's Unix DirAccess
counts mounted filesystems rather than Windows-style drive letters. The original premise for this
candidate ("the drives button can never be shown on Unix, so it need never be built") was WRONG,
and this verification is what caught it. The win is real but comes from ordinary
deferral-until-first-use, not from the button being unreachable.
