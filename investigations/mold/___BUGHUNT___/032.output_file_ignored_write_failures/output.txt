   the output size vs. stdio's buffer (patched build, temporarily
   instrumented with branch markers, then reverted)
=================================================================

$ build-plain/mold -o /dev/full -e _start scratch/mini.o          # 3360 bytes

exit=1

$ python3 scratch/limit.py 1024 scratch/b1.bin build-plain/mold -o - -e _start scratch/mini.o
mold: fatal: [fclose-branch] cannot write to -: File too large
exit=1

$ python3 scratch/limit.py 4096 scratch/b2.bin gcc -B build-plain -o - scratch/hello.o   # 8280 bytes
mold: fatal: [fwrite-branch] cannot write to -: File too large
collect2: error: ld returned 1 exit status
exit=1

-> An output smaller than stdio's buffer is fully absorbed by fwrite (which
   therefore returns success); the error only surfaces from fclose's flush.
   A check on fwrite alone would have left every small-output case silent.
