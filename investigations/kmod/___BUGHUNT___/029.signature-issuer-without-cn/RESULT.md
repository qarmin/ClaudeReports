# signature-issuer-without-cn: a PKCS#7 issuer without a CN reports its last RDN as the signer

`x509_name_to_str()` (libkmod/libkmod-signature-openssl.c) is meant to return the issuer's common name. When the issuer has entries but none is a CN, the loop ends with `nid` holding the NID of the last entry, the `nid == -1` check does not fire, and the function returns that last entry's value. `modinfo -F signer` (and `kmod_module_get_info()` key `signer`) then shows e.g. `PL` for an issuer `O=Foo Org, C=PL` instead of no signer.

## What was tried

| Approach/tool | Config (build/input/duration) | Outcome |
|---|---|---|
| Read the code of the three signature backends (`libkmod-signature.c`, `-openssl.c`, `-mbedtls.c`) | HEAD | the `nid` fall-through in `x509_name_to_str()` stood out; trailer length checks in `kmod_module_signature_info()` are sound |
| Real `modinfo -F signer` on a module signed with `openssl smime -sign` (`repro/`) | HEAD ASAN build, issuer `/O=Foo Org/C=PL` vs `/O=Foo Org/CN=My CN/C=PL`, 5 runs | 5/5 prints `PL` for the no-CN issuer, `My CN` for the CN one |
| Same repro after the fix | patched ASAN build, 5 runs | 5/5 prints an empty signer for no-CN, `My CN` unchanged |

## Status

**Confirmed** - deterministic, 5/5 on HEAD.

**Fully reproducible**: **Yes** - real `modinfo` binary on a module carrying a real openssl-produced PKCS#7 blob (self-signed certificate generated by the repro itself).

## Class

logic (wrong `signer` reported for a signed module)

## Root cause

`nid` is initialised to -1 and overwritten on every iteration; only the `NID_commonName` iteration breaks out. After a loop that found no CN, `nid` is the last entry's NID (any value except -1) and `e` points at that entry, so `ASN1_STRING_get0_data()` returns an unrelated RDN. Only an issuer with zero entries returns NULL.

## Introduced by

391b471 "libkmod-signature: implement pkcs7 parsing with openssl" (moved to the current file by 434bf35).

## The fix

`patch.diff` (+1/-1): `if (nid != NID_commonName) return NULL;` so only an actual CN is returned.

Project test suite (`tools/run_tests.sh`, ASAN/UBSAN): 7/7 OK before -> 7/7 OK after. `just test` in the candidate folder run end to end (clone, build, before, apply, after).

## What's not done / open questions

- The mbedtls backend (`libkmod-signature-mbedtls.c`) was not built here (`-MBEDTLS`); it takes the issuer differently and was not compared.
- The returned CN is taken from `ASN1_STRING_get0_data()` and measured with `strlen()`, so a non-UTF8/BMPString CN would be cut at the first NUL byte; not explored.
- "Before" in `output.txt` ran against the workspace's `__build-asan` (main tree), which differs from HEAD only in the user's uncommitted `libkmod-index.c` change, unrelated to signatures.
