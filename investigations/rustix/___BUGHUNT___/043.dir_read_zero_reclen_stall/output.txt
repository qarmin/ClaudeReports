This is the real `Dir::read_from`/`Iterator::next` public entry point, fed a `buf` that was
populated by one genuine `getdents64` syscall on a real temp directory, with only the two
`d_reclen` bytes of the next record corrupted to 0 (standing in for what a buggy getdents64

every one of 50,000 straight `.next()` calls re-parses the exact same corrupted bytes and returns
the exact same `DirEntry`, with `any_errors` never set - this is the unbounded stall the
candidate description predicts, demonstrated against the real parsing code rather than a
reimplementation of it. Reproduced 5/5 runs (bit-for-bit identical panic message every time, debug
