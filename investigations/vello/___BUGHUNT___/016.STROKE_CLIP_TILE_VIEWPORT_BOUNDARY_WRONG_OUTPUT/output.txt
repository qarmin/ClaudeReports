=== Approach 1: vello_tests headless GPU-vs-"CPU" comparison test (AaConfig::Area) ===

Added `stroke_rect_touching_viewport_boundary` to
`vello_tests/tests/known_issues.rs`, calling `vello_tests::compare_gpu_cpu_sync` (the project's
own real `Renderer::render_to_texture` public entry point, `use_cpu=false` vs `use_cpu=true`) with
the reporter's exact scene and a 1044x800 canvas (the `simple` example's own window size).

$ cargo test -p vello_tests --test known_issues stroke_rect_touching_viewport_boundary -- --nocapture
running 1 test
test stroke_rect_touching_viewport_boundary ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 2 filtered out; finished in 3.96s

Note: `use_cpu` only toggles which device runs the `pathtag_scan` stage (a Rust CPU fallback for
one pipeline stage) - the coarse/tile-alloc/backdrop/fine WGSL shaders that would contain a
viewport-boundary bug run identically either way on this machine (both dispatch through the same
llvmpipe/Gl adapter), so this comparison is not an independent oracle for this specific bug class;
it is included for completeness since it was the first thing tried.

Manual pixel inspection of the actual rendered PNG (via VELLO_DEBUG_TEST=all) found the rendered
image's only non-background pixels exactly bounding the expected stroked-rect outline, with zero
stray pixels anywhere else across the full 1044x800 canvas:

$ python3 -c "... scan every pixel, print (count, minx, maxx, miny, maxy) of non-background pixels ..."
328 113 216 0 61

(328 non-background pixels, bounding box x=[113,216] y=[0,61] - matches the expected 1px-wide
outline of Rect::from_origin_size((113.5,0.5),(103.0,61.0)) exactly: perimeter of a 103x61 rect
outline is 2*(103+61)-4 = 328.)

=== Approach 2: install a real (or software) Vulkan backend to get closer to a genuine GPU compute path ===

No root access (`sudo` refused: "no new privileges" flag set) and no Vulkan ICD package available
via the configured apt sources (`apt-get download mesa-vulkan-drivers` -> "no candidate", network
itself IS reachable - confirmed via `curl -sI https://google.com` - but the vulkan/lavapipe package

hardware Vulkan/Metal/DX12 backend either. This approach was abandoned as infeasible in this
session rather than yielding a negative result.
