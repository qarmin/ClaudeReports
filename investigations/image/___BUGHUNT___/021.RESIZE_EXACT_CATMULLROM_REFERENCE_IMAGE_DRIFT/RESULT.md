## Status

**Confirmed.** Deterministic, no layout/seed/timing dependence: 3/3 identical runs of the
standalone `repro/`, plus the real `cargo test` in the main tree failing the same way both before
and after the (reverted) `pic-scale-safe` patch experiment.

**Fully reproducible: Yes.** `repro/`'s `main.rs` calls only `image::DynamicImage::resize_exact`,
the crate's real public API, on a real `DynamicImage` decoded from a real PNG via the crate's own
public `ImageReaderOptions`/`decode()` path - the same call the real `tests/regression.rs` test
itself makes. This is a pure, single-process computational comparison against a static committed
reference file, not a reaction to another participant's live input, so `CONFIRMATION.md` section
11's "real second participant" requirement does not apply.

## Root cause

**Not confirmed** - same as the original `___OTHER___/003` report, and this candidate's own added
work narrows but does not close the gap:

- It is **not** (solely) candidate 017/018's window-misalignment bug: applying that fix to a local
  patched `pic-scale-safe` clone and re-running both the real `cargo test` and this candidate's own
  diff-count check makes the mismatch against the committed reference image measurably **larger**
  (13 -> 316 differing channels, max diff 1 -> 8), not smaller. The most likely explanation is that
  the committed reference PNG (`resize-with-alpha-original-half-size.png`) was itself generated by
  a build of `pic-scale-safe` that *already had* the window-misalignment bug (its output is very
  close, but not identical, to the current unpatched dependency's output) - so "fixing" the window
  bug correctly moves live output further from a reference image that itself encodes the buggy
  behavior as ground truth. This does not mean candidate 017/018's fix is wrong; it means this
  particular regression test's reference image would need regenerating against any future
  `pic-scale-safe` release that includes that fix, which is a decision for the project maintainers,
  not something this candidate can resolve by patching `image`'s own source.
  `___OTHER___/003`'s original report already ruled out the declared minimum `pic-scale-safe =
  "0.1.5"` as the reference's origin (that version diverges far more, up to 255, not 1) - combined
  with this session's finding, the reference most plausibly came from some `pic-scale-safe` version
  between `0.1.5` and `0.1.11` that already exhibits the same window-alignment behavior as `0.1.11`
  but was compiled/optimized slightly differently (a different `rustc`/target-feature/SIMD
  code path can legitimately shift the last bit of a floating-point convolution sum). That specific
  version was not identified this session either.
- Both `___OTHER___/003`'s original scope and this candidate's own re-check only exercised one
  fixed source/target/filter combination (129x66 -> 65x33 RGBA, `CatmullRom`) - whether the same
  ~0.15%-of-channels, `|diff|<=1` drift pattern holds at other sizes/filters against a from-scratch
  reference (not the one committed to the repo) was not checked.

## The fix

**No bounded fix found this session.** The candidate loop's own hypothesis (that this is downstream
of the already-identified and already-fixed candidate 017/018 `pic-scale-safe` bug) was tested
directly and ruled out - see "Root cause" above. Finding the actual source of this specific 1-LSB
drift would require either identifying the exact `pic-scale-safe`/`rustc` combination the committed
reference PNG was generated with, or deciding to regenerate that reference image against a current
dependency version (a project-maintainer decision, not a code fix) - both out of scope for a single
candidate session.

- Project test suite: `cargo test --release --test regression resizing_with_catmul` - **failing
  before** (unpatched tree) **-> still failing after** (with candidate 017's unrelated
  `pic-scale-safe` fix experimentally applied and then reverted). No fix was applied to the main
  project's own source this session, so the full suite was not otherwise re-run for this candidate.
