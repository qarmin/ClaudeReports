=== approach 2: manual boundary-value construction, release build (no overflow-checks), pristine tree ===
Two-spine tree (see repro/src/main.rs): a single root splits into spine A (local width 0)
and spine B (local width 1); each spine keeps expanding with branching factor 3, only its
own last local child (index 2) continues, for 42 levels (3^42 ~ 1.09e20 >> usize::MAX ~
1.8e19 on 64-bit, so the encoded sort key must overflow partway through). Correctness
invariant checked: since A's path key started strictly smaller than B's and the identical
recurrence is applied to both, every A-lineage element visited at a given tree depth must
sort strictly before every B-lineage element visited at that same depth, under the
documented default `IterationOrder::Ordered` - unless the encoded usize key has overflowed.
